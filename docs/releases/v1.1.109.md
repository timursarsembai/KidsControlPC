First release since v1.1.101. Agents built in between could die at startup, could not
authenticate, and could be wiped out by their own auto-update. Install this build
manually on every child PC rather than waiting for the updater.

## Agent no longer dies on its own

- **Fixed: the agent never started at all on a fresh install.** `Sentry.init()` ran at
  module scope and threw `TypeError: undefined is not a function`, because pkg embeds
  Node.js 18.5 while `@sentry/node` 10.x requires 18.19+. The process died before the
  pairing prompt, so installation appeared to succeed and the agent simply was not
  there. Present since v1.1.103; v1.1.101 predates Sentry, which is why older machines
  kept working.
- **Fixed: sleep/resume killed the agent.** Three failed heartbeats triggered
  `process.exit(1)`. On Windows 11 Modern Standby the NIC returns seconds after resume,
  and Firestore's `updateDoc` only settles once the server acknowledges it, so every
  resume guaranteed three timeouts. The Firestore channel is now reset in place instead.
- **Fixed: rules were not enforced while the network was down.** Enforcement was
  scheduled at the very end of startup, after network calls that had no timeout, so a
  slow connection left the service running with nothing blocked. Enforcement now starts
  first and runs from the on-disk rule cache.

## Authentication actually works

- `callCF()` never sent an `Authorization` header, so `registerAgentUid` always failed.
- Pairing signed in anonymously and persisted that session, permanently shadowing the
  device's real identity.
- `@firebase/auth` takes `fetch` from `undici`, which does not work under pkg, so
  `signInWithCustomToken` always failed and the agent silently ran unauthenticated.

All three are fixed; auth is retried if the network is unavailable at boot, and dead
Firestore listeners now re-subscribe instead of leaving the agent on stale rules.

## Installer no longer destroys the installation

A silent update stopped the service, ran `sc delete`, then failed to overwrite
`WinSW.exe` because the service host still held it. With no dialog to answer, the
install aborted — leaving the machine with no service and no agent until someone
reinstalled by hand. This is why agents disappeared over time. Running processes are
now stopped and their binaries renamed aside before files are replaced.

Also removed a `taskkill /F /IM node.exe` that killed every unrelated Node process on
the machine.

## Security

Device documents, installed-app lists and activity logs were readable and writable by
anyone who knew a user id and device id, and alerts and chat messages were writable by
anyone at all. Agents now prove their identity with a signed token and the fallbacks
are gone. **Agents older than 1.1.106 can no longer connect.**

## Behaves under load

A child PC kept dropping offline with 462 MB free of 7.7 GB, five days of uptime, and
Edge, Roblox, a torrent client and Defender holding roughly 2.5 GB between them. The
agent was not the cause — 45 MB resident, no leak — but it spawned a fresh
`powershell.exe` on every 5-second enforcement tick, and that spawn is the first thing
to fail on a machine with no memory left. Retrying it every 5 seconds added load where
there was none to spare.

Scans now back off after a failure: 15 seconds, doubling to a 5-minute cap, resetting
on the first success. Enforcement continues from the cached rules throughout, so
blocking is unaffected; the only change is that a struggling machine is left alone.

Free and total memory are now logged when a scan fails and when the Firestore
connection is reset. An out-of-memory machine and a genuinely disconnected one produce
identical `ENETUNREACH` and timeout symptoms, and nothing in the log told them apart.

## Also

- Reinstalling an agent on a replacement PC keeps that device's rules and settings —
  use "Код для переустановки" on the device card instead of pairing a new device.
- The enforcer no longer writes its full rule list to the log every 5 seconds, and the
  Windows hosts file is only rewritten when its contents actually change.
- Expired screenshots are cleaned up again; the agent had never been allowed to read
  its own screenshot collection, so they accumulated against the storage quota.
