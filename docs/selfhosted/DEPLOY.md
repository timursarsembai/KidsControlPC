# Выкладка self-hosted версии

Что нужно сделать руками, когда домен `kidscontrol.kz` делегируется.
На 23.08.2026 NS-записей у домена ещё нет, поэтому наружу пока ничего не
опубликовано — стек работает только на localhost сервера.

## Что уже поднято

```

kidscontrol-api   Node 22              127.0.0.1:8092
kidscontrol-web   nginx + панель       127.0.0.1:8094
```

Управление: `cd ~/docker/kidscontrol/repo/server && docker compose ...`
Секреты — в `server/.env`, в репозиторий не попадают.

## DNS

Две A-записи на **93.171.232.110** (это адрес самого сервера):

```
kidscontrol.kz          A   93.171.232.110
api.kidscontrol.kz      A   93.171.232.110
```

`www` — по желанию; сервер отвечает и на него, CORS его уже разрешает.

## Nginx Proxy Manager

Панель `81` доступна только с localhost, поэтому идти туда через «Проходную»
(`~/gatehouse`) или через туннель.

**Хост 1 — панель.**

| Поле | Значение |
|---|---|
| Domain Names | `kidscontrol.kz` |
| Scheme | `http` |
| Forward Hostname | `kidscontrol-web` |
| Forward Port | `80` |
| Block Common Exploits | включить |
| SSL | запросить сертификат Let's Encrypt, Force SSL, HTTP/2 |

**Хост 2 — API.**

| Поле | Значение |
|---|---|
| Domain Names | `api.kidscontrol.kz` |
| Scheme | `http` |
| Forward Hostname | `kidscontrol-api` |
| Forward Port | `8092` |
| **Websockets Support** | **включить обязательно** |
| SSL | запросить сертификат Let's Encrypt, Force SSL, HTTP/2 |

Без галочки Websockets живая доставка не работает: правила и команды будут
доходить до детского ПК только при следующем опросе, а панель перестанет
обновляться сама. Симптом обманчивый — всё «работает», просто с задержкой.

## После публикации проверить

```bash
curl -s https://api.kidscontrol.kz/health          # ok=true, realtime=up
curl -s -o /dev/null -w '%{http_code}\n' https://kidscontrol.kz/
```

Затем в браузере: регистрация, код привязки, и — главное — что карточка
устройства оживает сама, без перезагрузки страницы. Это и есть проверка того,
что WebSocket прошёл через прокси.

## Агент

Собирается на домашнем ПК с Windows (здесь нет ни Windows, ни .NET):

```powershell
npm run build:selfhosted --prefix agent
```

Отличие от обычной сборки — одна константа, зашитая в исполняемый файл
(`KIDSCONTROL_BACKEND=selfhosted`). Обычная сборка по-прежнему собирает
Firebase-агента, и это намеренно: агенты на детских ПК обновляются сами с
GitHub Releases, и сборка, случайно сменившая бэкенд, увела бы их на сервер,
с которым они никогда не были связаны, — то есть оставила бы без правил.

Адрес сервера берётся из `KIDSCONTROL_API_BASE_URL`, по умолчанию
`https://api.kidscontrol.kz`.

**Такой агент нельзя выкладывать в тот же GitHub Release, что и боевой.**
Обновление не различает сборки: боевые агенты скачают его и переедут на
чужой для них сервер. Для проверки — ставить вручную.

Что уже проверено на этом сервере (в контейнере, не на Windows): привязка по
коду, обмен секрета на токен, доставка правил и команд за ~150 мс, отчёт о
выполнении, активность, уведомления, работа при отзыве доступа. Проверить на
живой Windows-машине ещё предстоит — именно там живут привязка к экрану,
блокировка процессов и служба.

## Почта

Восстановление пароля и подтверждение адреса готовы, но выключены: в `.env`
пусто в `SMTP_HOST`. Пока так, панель не показывает ссылку «Забыли пароль» —
форма, которая молча ничего не делает, хуже её отсутствия.

Когда `kidscontrol.kz` делегируется:

1. в mailcow добавить домен `kidscontrol.kz` и ящик `noreply@kidscontrol.kz`;
2. прописать для домена SPF, DKIM и DMARC — без них письма уедут в спам,
   а восстановление пароля в спаме равносильно его отсутствию;
3. дать контейнеру API доступ к сети mailcow — по умолчанию он её не видит,
   и имя почтового контейнера у него не разрешается (проверено). В
   `server/compose.yaml` у сервиса `api` добавить сеть, и в конце файла:

```yaml
  api:
    networks:
      - internal
      - proxy-network
      - mailcow          # ← добавить

networks:
  mailcow:
    external: true
    name: mailcowdockerized_mailcow-network
```

   Второй путь — слать на внешний адрес сервера (`93.171.232.110:587`): он
   тоже работает, но гоняет письма наружу и обратно ради соседнего контейнера.

4. заполнить в `server/.env`:

```
SMTP_HOST=mailcowdockerized-postfix-mailcow-1
SMTP_PORT=587
SMTP_USER=noreply@kidscontrol.kz
SMTP_PASS=<пароль ящика>
MAIL_FROM=KidsControlPC <noreply@kidscontrol.kz>
```

5. `docker compose up -d api` и проверить:

```bash
curl -s https://api.kidscontrol.kz/api/v1/auth/capabilities
# {"passwordReset":true,"emailVerification":true}
```

Отправлять с `@kazpayment.kz` нельзя: письмо про родительский контроль с
адреса платёжного проекта выглядит как фишинг — и для получателя, и для
почтовых фильтров.
