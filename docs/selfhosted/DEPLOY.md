## Nginx Proxy Manager

Панель `81` доступна только с localhost, поэтому идти туда через «Проходную»
(`~/gatehouse`) или через туннель.

**Хост 1 — панель.**

| Поле | Значение |
|---|---|
| Domain Names | `kidscontrol.kz` |
| Scheme | `http` |
| Forward Hostname | `kidscontrol-web` |
| Forward Port | `80` |
| Block Common Exploits | включить |
| SSL | запросить сертификат Let's Encrypt, Force SSL, HTTP/2 |

**Хост 2 — API.**

| Поле | Значение |
|---|---|
| Domain Names | `api.kidscontrol.kz` |
| Scheme | `http` |
| Forward Hostname | `kidscontrol-api` |
| Forward Port | `8092` |
| **Websockets Support** | **включить обязательно** |
| SSL | запросить сертификат Let's Encrypt, Force SSL, HTTP/2 |

Без галочки Websockets живая доставка не работает: правила и команды будут
доходить до детского ПК только при следующем опросе, а панель перестанет
обновляться сама. Симптом обманчивый — всё «работает», просто с задержкой.

## После публикации проверить

```bash
curl -s https://api.kidscontrol.kz/health          # ok=true, realtime=up
curl -s -o /dev/null -w '%{http_code}\n' https://kidscontrol.kz/
```

Затем в браузере: регистрация, код привязки, и — главное — что карточка
устройства оживает сама, без перезагрузки страницы. Это и есть проверка того,
что WebSocket прошёл через прокси.

## Агент

Собирается на ПК с Windows (здесь нет ни Windows, ни .NET). Полный порядок для
чистой машины — `docs/selfhosted/BUILD-AGENT.md`; коротко:

```powershell
git clone https://github.com/timursarsembai/KidsControlPC
cd KidsControlPC && git checkout selfhosted
cd agent && npm install
npm run build:selfhosted
```

Отличие от обычной сборки — одна константа, зашитая в исполняемый файл
(`KIDSCONTROL_BACKEND=selfhosted`). Обычная сборка по-прежнему собирает
Firebase-агента, и это намеренно: агенты на детских ПК обновляются сами с
GitHub Releases, и сборка, случайно сменившая бэкенд, увела бы их на сервер,
с которым они никогда не были связаны, — то есть оставила бы без правил.

Адрес сервера берётся из `KIDSCONTROL_API_BASE_URL`, по умолчанию
`https://api.kidscontrol.kz`.

**Такой агент нельзя выкладывать в тот же GitHub Release, что и боевой.**
Обновление не различает сборки: боевые агенты скачают его и переедут на
чужой для них сервер. Для проверки — ставить вручную.

Что уже проверено на этом сервере (в контейнере, не на Windows): привязка по
коду, обмен секрета на токен, доставка правил и команд за ~150 мс, отчёт о
выполнении, активность, уведомления, работа при отзыве доступа. Проверить на
живой Windows-машине ещё предстоит — именно там живут привязка к экрану,
блокировка процессов и служба.

## Почта

Отправляет отдельный контейнер `kidscontrol-mail` (сервис `mail` в compose):
доставляет прямо на MX получателя и подписывает своим ключом DKIM. Портов
наружу не публикует — доступен только контейнеру API.

**Почему не mailcow.** Там весь исходящий поток идёт релеем через Resend одним
аккаунтом, чей бесплатный план покрывает один домен — платёжного проекта.
Развести домены по релеям означало бы править конфигурацию Postfix живого
почтового сервера, от которого зависят чужие деньги, ради домена, шлющего
десяток писем в месяц.

Записи в DNS (добавлены 24.08.2026):

```
mail._domainkey   TXT   v=DKIM1; h=sha256; k=rsa; s=email; p=…
_dmarc            TXT   v=DMARC1; p=none; rua=mailto:…
```

SPF (`v=spf1 +a +mx include:_spf.ps.kz -all`) покрывает сервер через `+a`.

Ключ DKIM лежит в томе `kidscontrol_dkim` и переживает пересборку. **Если том
потерять, все подписи перестанут проверяться**, пока новый ключ не окажется в
DNS — том входит в резервное копирование как часть каталога проекта.

`SMTP_ALLOW_SELF_SIGNED=true` в `.env` — сертификат у локального отправщика
самоподписанный, а соединение не покидает docker-сеть. Для внешнего провайдера
эту настройку включать нельзя: там сертификат и есть доказательство, что вы
говорите именно с ним.

Проверка:

```bash
curl -s https://api.kidscontrol.kz/api/v1/auth/capabilities
# {"passwordReset":true,"emailVerification":true}
docker logs kidscontrol-mail --since 5m | grep "status=sent"
```

Обратная запись адреса — `vds35755.vpsza500.kz`, домену не соответствует.
Gmail такие письма принимает при валидных SPF и DKIM; Mail.ru и Yandex строже.
Если письма начнут попадать в спам, следующий шаг — отдельный бесплатный релей
(Brevo, SMTP2GO, MailerSend) для этого домена, через `SMTP_HOST`/`SMTP_USER`;
менять больше ничего не придётся.

## Скриншоты и резервные копии

Файлы (скриншоты и вложения чата) лежат в томе `kidscontrol_files` и в офсайт
**не уезжают**. Это осознанно: вторая площадка (Contabo) за пределами
Казахстана, а скриншоты — самое чувствительное, что здесь есть, и они сами
удаляются через трое суток. Копировать их за границу ради трёхдневных данных —
плохой размен.

**Дамп базы в офсайт уезжает, и это решено оставить как есть** (24.08.2026,
решение владельца). В нём активность, посещённые сайты и имена устройств.
Обоснование: restic шифрует репозиторий, пароль хранится отдельно от данных, а
сам репозиторий разделён на две части с разными паролями.

Что при этом стоит помнить, если вопрос всплывёт снаружи: шифрование
закрывает утечку, но не отменяет того, что копия физически находится за
пределами РК. Если однажды понадобится закрыть и это, менять придётся немного
— перенести репозиторий restic на площадку в РК; состав дампа и скрипты
останутся прежними.
