# Перенос данных из Firebase

Два скрипта: экспорт читает живой Firestore, импорт кладёт прочитанное в
PostgreSQL. Экспорт ничего не пишет в Firebase — версия на Firebase должна
продолжать работать всё время переезда и после него.

## Порядок

Прогонов будет два: репетиция и настоящий. Импорт написан идемпотентным
именно поэтому — второй прогон обновляет то, что перенёс первый, и не трогает
ничего, что успел создать этот сервер.

### 1. Экспорт (там, где лежит ключ сервисного аккаунта)

Ключ берётся в консоли Firebase: «Настройки проекта» → «Сервисные аккаунты» →
«Создать закрытый ключ». Права нужны только на чтение.

```bash
npm install firebase-admin        # разово, в любом каталоге
node export-firestore.mjs --key ./serviceAccount.json --out ./export.ndjson
```

По умолчанию берётся активность за 30 дней: год событий по каждому приложению
— это миллионы строк, которые никто не откроет. `--activity-days 0` пропустит
её целиком, большее число возьмёт больше.

На выходе — NDJSON, по строке на родителя. Формат читаемый: перед импортом в
него полезно заглянуть.

**Ключ сервисного аккаунта после экспорта удалить.** Он открывает весь проект
Firebase, и лежать «до следующего раза» ему негде.

### 2. Импорт

```bash
docker cp export.ndjson kidscontrol-api:/tmp/export.ndjson
cd ~/docker/kidscontrol/repo/server

docker compose exec api node scripts/import-firestore.mjs --file /tmp/export.ndjson --dry-run
docker compose exec api node scripts/import-firestore.mjs --file /tmp/export.ndjson
```

Сначала `--dry-run`: он ничего не пишет и показывает, сколько чего приедет.
Если числа не похожи на правду, разбираться нужно до записи, а не после.

Файл кладётся в `/tmp` контейнера и исчезает при его пересоздании — это не
хранилище, а передача.

### 3. Пароли

Не переносятся. Firebase отдаёт их scrypt-хешами со своими параметрами, и
повторять этот алгоритм ради разовой задачи — писать криптографический код,
который сразу выбрасывается.

Импорт печатает временный пароль на каждый **новый** аккаунт. Этот вывод
больше нигде не сохраняется: скопировать сразу. Родителям пароли передаются
лично, и первым делом они меняют их в панели: Настройки → Аккаунт → Смена
пароля.

При повторном прогоне пароль уже существующего аккаунта не трогается — иначе
настоящий прогон обнулил бы то, что родители сменили после репетиции.

### 4. Устройства

Переносятся вместе с правилами, историей и названиями, которые дал родитель,
но **без секретов**. Секрет — это то, чем агент доказывает, кто он; секрет из
Firebase здесь бесполезен, а перенесённый выглядел бы как рабочий и делал бы
устройство «подключённым», когда оно не подключено.

Поэтому после переезда на каждый детский ПК ставится новая сборка агента и
делается **ремонтная привязка** (Настройки → Устройства → «Перепривязать»):
она пишет в то же устройство, поэтому правила, история и название остаются на
месте.

Порядок на одну машину:

1. родитель в панели получает ремонтный код на это устройство;
2. на детском ПК ставится агент, собранный с `KIDSCONTROL_BACKEND=selfhosted`;
3. вводится код — устройство оживает со своими прежними правилами.

### 5. Что не переносится

- **Чат и вложения**, **скриншоты** — отложены, на этом сервере их нет.
- **Приглашения второго родителя и его доступы** — отложены.
- **Секреты устройств** — см. выше.
- **Активность старше окна экспорта** — по умолчанию 30 дней.

Firebase при этом остаётся нетронутым: если что-то пойдёт не так, старая
версия продолжает работать, а импорт можно повторить.

## Что уже проверено

На синтетическом наборе в формате экспорта: аккаунты, профили, устройства с
настройками (включая активную блокировку экрана), правила с фиксированными
именами и без, программы, статистика с вложенными счётчиками, уведомления —
в том числе от устройства, которого больше нет.

Проверено и главное для второго прогона: между репетицией и настоящим
импортом на сервере появились новые уведомление и событие — повторный прогон
обновил только своё и не тронул их.

**Не проверено:** экспорт из живого Firestore. Ключа сервисного аккаунта у
меня нет, и первый запуск экспорта будет первым по-настоящему. Начинать
стоит с одного аккаунта — в экспорте видно, что получилось, ещё до импорта.
